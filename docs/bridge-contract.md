# Bridge contract (Mobile-v1)

The observable behaviour of the Orsik Mobile Bridge, frozen before the Rust
port. Every row is checked by the black-box suite in
[`bridge-rs/contract`](../bridge-rs/contract), which starts a bridge as a
process against a fake Hermes and talks to it over HTTP only. The suite runs
against the Python bridge (`BRIDGE_PY`) and, once it exists, against the Rust
bridge (`BRIDGE_CMD`). A change to this contract changes the tests first.

Security reasoning behind the rules: [`bridge-security.md`](bridge-security.md).
Wire format the app expects: [`mobile-wire-contract.md`](mobile-wire-contract.md).

## Errors

Every error the bridge produces itself is `{"error": {"code": "<code>"}}`
with no echo of the request, no URL, no key and no internal detail.
Errors that come from Hermes keep their status and body (buffered bodies with
the master key replaced by `[redacted]`).

## Configuration and start-up

| Variable | Rule |
|---|---|
| `BRIDGE_UPSTREAM` | default `http://127.0.0.1:8642`; must be `http`, a loopback IP literal, an explicit port, no user info, path, query or fragment. Refused otherwise; the value is never echoed. |
| `BRIDGE_BIND` | default `127.0.0.1`; a literal loopback IP only (`localhost` is refused). |
| `BRIDGE_PORT` | default `9842`; 1–65535. |
| `BRIDGE_HERMES_ENV` | file with `API_SERVER_KEY`; must be a regular file owned by the bridge user with mode 0600, else refused. dotenv rules: `export ` prefix, quotes stripped, ` #` comment ends an unquoted value. |
| `HERMES_API_KEY` | fallback key; start is refused without any key. |
| `BRIDGE_ENV_FILE` | extra env file, same 0600 rule. |
| `BRIDGE_HOME`, `BRIDGE_STATE_DB` | store path, default `~/.local/orsik-mobile-bridge/state.db`. |
| `BRIDGE_HOST_SERVICES` | up to 8 unit names `[A-Za-z0-9][A-Za-z0-9@_.-]{0,63}` (a `.service` suffix is dropped); default `hermes-gateway,orsik-mobile-bridge`. |
| `BRIDGE_TERMINAL` | `1` on, `0`/empty off, anything else refused; on needs `tmux` and `setsid` on the PATH. |
| `BRIDGE_FILES`, `BRIDGE_FILES_ROOT` | `1` needs an existing absolute directory that is not `/`, does not contain the home folder, the bridge home, the store, the env files or the Hermes home, and does not lie inside the bridge or Hermes home. |
| `BRIDGE_TRUST_TAILSCALE_IDENTITY` | `1`: the pairing rate limit keys on `Tailscale-User-Login` from loopback. |
| `BRIDGE_PUBLIC_BASE_URL` | default base URL of the pairing deep link. |

Files the bridge creates are never group/world accessible (umask 077).

## Routes

Device key: `Authorization: Bearer hd_…`. Missing or unknown → 401 `invalid_credentials`.
A store failure on any route → 503 `store_unavailable` (never fail open).
Request bodies are bounded to 10 000 000 bytes (413).

| Route | Auth | Rules |
|---|---|---|
| `GET /health` | none | proxied to Hermes; a request body → 400 `body_not_allowed`. |
| `GET /v1/capabilities` | key | generated by the bridge; exact Mobile-v1 shape. `terminal` only when the terminal is on **and** the device holds the grant; `files`/`projects` only when files are on. |
| `GET /v1/host/metrics` | key | `orsik.host.metrics` snapshot (CPU over 0.2 s, memory, first NVIDIA GPU, `systemctl --user is-active` per service: `true`/`false`/`null` for unknown), cached 5 s; query → 403 `query_not_allowed`, body → 400 `body_not_allowed`. |
| `POST /v1/devices/pair` | none | rate limited 60/min per peer (429 `rate_limited`); `Content-Type: application/json` and exactly `{"code"}` (400 `invalid_json` / `invalid_fields` / `pairing_code_invalid`); 201 with the seven credential fields; 503 `device_capacity_reached`. |
| `POST /v1/devices/self/revoke` | key | exactly 0 bytes (key checked first); 200 `{"revoked", "device_id"}`. |
| `POST /v1/runs/{run_id}/approval` | key | run id ≤ 256, `[A-Za-z0-9_.-]` (400 `invalid_run_id`); body exactly `{"choice","request_id"}`, choice `once`/`deny`, request id non-blank, ≤ 256, no control characters (400 `invalid_json`/`invalid_fields`/`invalid_choice`/`invalid_request_id`). Forwarded canonical, plus `execution_generation` when `GET /v1/runs/{run_id}` answers 200 with an integer one. |
| `POST /api/sessions/{id}/chat/stream` | key | server-side takeover (below); session id `[A-Za-z0-9_.-]` (400 `invalid_session_id`); any query → 403 `query_not_allowed`; 503 `bridge_busy` with `Retry-After: 5` at 16 active runs. |
| `GET /api/sessions/{id}/runs/{run_id}/stream?after_seq=N` | key | re-attach (below); `after_seq` integer ≥ -1, default -1 (400 `invalid_after_seq`); malformed ids → 404 `run_not_found`. |
| `GET /v1/terminal` | key + grant | only with `BRIDGE_TERMINAL=1` (403 `endpoint_out_of_scope`), grant (403 `terminal_not_allowed`), no query, no `Origin` header (403 `origin_not_allowed`), WebSocket only (400 `websocket_required`), at most 4 at once (429 `terminal_limit`). |
| `GET /v1/files/list?path=`, `GET /v1/files/content?path=`, `GET /v1/projects` | key | only with `BRIDGE_FILES=1` (403 `endpoint_out_of_scope`); only the `path` key, once (403 `query_not_allowed`); no body. |
| everything else | key | the closed proxy allowlist below, else 403 `endpoint_out_of_scope`. |

### Proxy allowlist

Exact paths only (a trailing slash or any other spelling is refused). Path
segments must be `[A-Za-z0-9_.-]`, not `.`/`..`. Only `GET` on
`/api/sessions…` may carry the query keys `limit`, `offset`, `order`,
`include_children`. Hermes gets `Authorization: Bearer <master key>`,
the client's `Content-Type` and `Accept`, nothing else. Redirects are never
followed (502 `upstream_redirect`); an unreachable Hermes is 502
`upstream_unavailable`; a buffered body over 16 MiB (64 MiB for history
pages) is 502 `upstream_error_too_large`.

| Method and path | Extra rules |
|---|---|
| `GET /api/sessions`, `POST /api/sessions`, `GET /api/sessions/{id}` | — |
| `GET /api/sessions/{id}/messages` | history slimmed: image data dropped (parts keep their `type`), tool `content` emptied, `tool_calls`/`reasoning`/`reasoning_content` removed, core image-hint texts turned into caption + data-less `image_url` parts. |
| `PATCH /api/sessions/{id}` | exactly `{"archived": bool}` or `{"title": str}` (non-blank, ≤ 512, no C0/C1 control characters); 400 `invalid_json`/`invalid_fields`/`invalid_archived`/`invalid_title`. |
| `DELETE /api/sessions/{id}` | no body (400 `body_not_allowed`). |
| `POST /api/sessions/{id}/fork` | body exactly `{}`; ≤ 4096 bytes. |
| `POST /api/sessions/{id}/model` | exactly `{"provider","model"}`; provider `[A-Za-z0-9_.-]{1,80}`, model non-empty, ≤ 200, no whitespace, control characters or `::`; ≤ 4096 bytes. |
| `GET /api/model/options` | no body. |
| `GET /v1/runs/{run_id}` | — |
| `POST /v1/runs/{run_id}/stop`, `POST /v1/runs/{run_id}/steer` | — |
| `POST /v1/runs/{run_id}/resolve-unknown` | exactly `{"admission_id","execution_generation"}`; admission id like a request id, generation an integer ≥ 0 (not a bool). |

Fork, model, model options, patch and delete also need the `chat`
permission (403 `device_scope_denied`); paired devices have
`approvals, chat, runs`.

## Chat stream takeover

* The bridge holds the upstream SSE connection itself; a client that leaves
  does not end the run.
* Upstream non-200 or non-SSE answers are relayed with their status and body
  (bounded to 64 KiB, else 502 `upstream_error_too_large`).
* Frames are relayed byte-for-byte except:
  * `run.started` loses `user_message` (the image echo);
  * `approval.request` with all of `session_id, run_id, seq, ts, request_id`
    becomes exactly those plus the fixed description and choices
    `["once","deny"]`; one missing a field is relayed unchanged;
  * unused fields are dropped: `messages/usage/runtime` on `run.*`
    terminal events, `runtime` on `assistant.completed`,
    `preview/args` on `tool.*`, `delta` on `tool.progress`, `text` on
    `assistant.commentary`.
* A frame over 1 MiB (after the rewrites) ends the stream with
  `: bridge_upstream_frame_too_large`; nothing after it is relayed.
* Retention: 1000 frames / 4 MiB per run, 256 runs, 10 min after the end,
  64 MiB for finished runs in total.
* Re-attach replays frames with `seq > after_seq`, then follows live.
  `after_seq` below the evicted range → 409 `resume_gap`.
* No buffer for the run: `GET /v1/runs/{run_id}` decides — 200 → 409
  `resume_gap`, 404 → 404 `run_not_found`, redirect → 502
  `upstream_redirect`, anything else → 502 `run_state_indeterminate`.
  A run of another session → 404 `run_not_found`.
* Every 15 s without a frame: `: keepalive`. Every 15 s the key is re-checked;
  a revoked device gets `: bridge_revoked` and the stream ends (the run goes on).
  A slow client is dropped with `: bridge_overflow`.

## Terminal WebSocket

Binary frames are bytes both ways; a text frame must be exactly
`{"type":"resize","cols":1..500,"rows":1..300}`. Close codes: 1000 the shell
ended, 1008 `protocol` (bad control message), 4401 `revoked`, 4403
`terminal_revoked`. Messages up to 64 KiB. The child runs
`setsid --ctty tmux new-session -A -s orsik` in a minimal environment
(HOME, USER, LOGNAME, SHELL, PATH, TERM, LANG); closing ends the tmux client
only.

## Files and projects

* `path` is relative, ≤ 4096 characters, no NUL, no leading `/`, no `.`/`..`
  segment, and must stay inside the root after symlinks (403
  `path_not_allowed`); missing or not a regular file → 404 `not_found`;
  over 8 MiB → 413 `file_too_large`.
* List: folders first, then case-insensitive by name, at most 2000 entries
  (`truncated`); a link that leaves the root is listed as `other` without
  size or time.
* Content types: PNG/JPEG/WebP/GIF by extension, UTF-8 text without NUL as
  `text/plain; charset=utf-8`, else `application/octet-stream`; always
  `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`.
* Projects: git working trees in the root and up to two levels below, at most
  50, with branch, dirty state (`null` when unknown) and the last commit
  (short hash, time, subject ≤ 200). git runs without global/system config,
  hooks, fsmonitor, attributes drivers or submodules; 10 s per scan, cached 10 s.

## Store

SQLite at `BRIDGE_STATE_DB`, mode 0600, WAL. `PRAGMA user_version` 2:

```sql
pairing_codes(code_hash TEXT PRIMARY KEY, expires_at REAL, used INTEGER, created_at REAL)
devices(token_hash TEXT PRIMARY KEY, device_id TEXT, label TEXT, profile TEXT,
        permissions TEXT, revoked INTEGER, issued_at REAL, created_at REAL,
        terminal_allowed INTEGER CHECK (terminal_allowed IN (0, 1)))
```

Codes and keys are stored only as SHA-256 hex of the UTF-8 string. Codes:
24 characters of `ABCDEFGHJKMNPQRSTVWXYZ123456789`, 300 s, single use
(atomic `UPDATE … WHERE used = 0 AND expires_at >= now`), at most 1024 live.
Keys: `hd_` + 32 random bytes base64url (46 characters), at most 4096 active
devices. A newer schema is refused; an older one is backed up
(`state.db.pre-v<N>.bak`) and migrated one step per transaction.

## Operator CLI

`<bridge> admin` with the same environment:

| Command | Output / exit |
|---|---|
| `pairing-code [--base-url https://…]` | `Pairing code: XXXX-XXXX-XXXX-XXXX-XXXX-XXXX  (valid 300s, single-use)`, plus `Deep link:    orsik://pair?server=<url-encoded>&code=<code>` and a QR (via `qrencode`, input on stdin) for an HTTPS base URL without user info; another base URL → exit 1. |
| `list-devices` | one line per device: `<device_id>  active|revoked  <label>  [<profile>]  terminal=allowed|denied`; never a key. |
| `revoke-device <id>` | `revoked <id>`; unknown → exit 1 `no such device_id`. |
| `grant-terminal <id>`, `revoke-terminal <id>` | `terminal allowed|denied for <id>`; no active device → exit 1. |
| `backup <dest>` | atomic 0600 copy; an existing destination is never overwritten (exit 1). |

`setup` and `update` (the installer front ends) are covered by the
deployment work, not by this suite.
